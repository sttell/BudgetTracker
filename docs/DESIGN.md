# BudgetTracker — дизайн

Локальный трекер личного бюджета: ежедневные траты вносятся через AI-агента (диктовка, скриншоты банковских приложений) или руками в веб-интерфейсе; приложение считает остаток месячного бюджета и честный лимит на день и неделю.

## 1. Архитектура

```
Claude (Desktop / Code)              Браузер
голос/текст, скриншоты               ручной ввод, дашборд
        │ MCP (stdio)                 │ HTTP
        ▼                             ▼
  budget/mcp_server.py          budget/web (Flask)
        └──────────────┬──────────────┘
                       ▼
     budget/service.py — единственная точка записи:
     валидация, курсы, дубли, категории, фиксированные траты
                       ▼
                 data/*.json
```

- Без БД и контейнеров: Python-пакет `budget`, данные в JSON-файлах.
- Агент не видит формат хранения: только инструменты MCP, которые вызывают тот же `service.py`, что и веб.
- MCP-сервер запускается клиентом Claude по stdio, веб-сервер для работы агента не нужен.
- Изображения распознаёт сам агент (Claude); приложение получает уже структурированные траты.

## 2. Типы трат

| Тип (`kind`) | Как задаётся | Дневной бюджет | Аналитика |
|---|---|---|---|
| `fixed` — фиксированные ежемесячные | из списка в настройках, создаются 1-го числа | нет, вычитаются из таргета заранее | да |
| `regular` — регулярные | по умолчанию у любой траты | да | да |
| `irregular` — нерегулярные | отмечает пользователь | да, если не стоит «сверх бюджета» | да, отдельно |

Нерегулярная трата имеет флаг `over_budget` (галочка «сверх бюджета», по умолчанию выключена):
- выключен — трата вычитается из свободного остатка и влияет на лимиты, как регулярная;
- включён — трата не влияет на бюджет и видна только в аналитике (итог месяца: таргет, факт в бюджете, плюс траты сверх бюджета).

## 3. Логика бюджета

Все суммы — в базовой валюте. Лимиты не хранятся, а каждый раз считаются из трат, поэтому поздно внесённые траты корректно пересчитывают историю.

- **Таргет месяца** `T` — задаёт пользователь. Таргет действует с указанного месяца и дальше, пока не задан новый.
- **Фиксированные** `F` = сумма трат `fixed` месяца (фактических, с учётом правок).
- **Свободный остаток месяца** `P = T − F`.
- **Траты в бюджете за день** `s(d)` = `regular` + `irregular` без `over_budget`.
- **Лимит на день D** = `max(0, P − Σ s(d) за d < D) / (дней от D до конца месяца, включая D)`.
- **На сегодня осталось** = лимит на сегодня − `s(сегодня)` (может быть отрицательным — перерасход дня).
- **Остаток на месяц** = `P − Σ s(d) за d ≤ сегодня`.
- **На неделю осталось** = лимит на сегодня × дней от сегодня до воскресенья (не дальше конца месяца) − `s(сегодня)`. Неделя начинается с понедельника.
- Перерасход или экономия дня автоматически распределяется поровну на оставшиеся дни.
- Если свободный остаток исчерпан, лимит показывается как 0, плюс сумма перерасхода по месяцу.

Пример: `T = 3000 €`, фиксированные 1500 + 200 + 280 = 1980 €, `P = 1020 €`, в октябре 31 день. Лимит 1 окт = 1020/31 = 32.90; потрачено 50 → лимит 2 окт = 970/30 = 32.33; потрачено 10 → лимит 3 окт = 960/29 = 33.10.

**Итог месяца (аналитика):** таргет; фиксированные; траты в бюджете; итого в бюджете и отклонение от таргета; траты сверх бюджета; всего потрачено.

## 4. Фиксированные траты

- Шаблоны (название, сумма, валюта, категория) задаются в настройках. Шаблон действует с месяца создания.
- При первом обращении к наступившему месяцу, у которого есть таргет, траты из действующих шаблонов создаются датой 1-го числа (`kind=fixed`). Каждый шаблон применяется к месяцу один раз: удалённая из месяца фиксированная трата не появится снова.
- Правка суммы в месяце (коммуналка пришла 185 вместо 200) меняет только этот месяц; шаблон не меняется. Изменение шаблона влияет на месяцы, где он ещё не применён.
- Агент сопоставляет оплаты из скриншотов с фиксированными тратами месяца и не добавляет их второй раз (при отличии суммы — правит её).

## 5. Валюты

- Валюты: RSD, EUR, USD. **Базовая валюта** (отображение, бюджет) и **валюта ввода по умолчанию** выбираются в настройках.
- Трата хранит исходную сумму и валюту; в базовую пересчитывается при отображении по курсу на дату траты. Смена базовой валюты пересчитывает всю историю.
- Курс — официальный средний курс Народного банка Сербии (НБС) через публичный API `kurs.resenje.org` (зеркало курсового листа НБС; на выходные отдаёт лист последнего рабочего дня). EUR↔USD — кросс-курс через RSD.
- **Реальный курс обмена**: для EUR и USD в настройках хранится коэффициент к курсу НБС (`rate_adjustments`); пересчёт идёт по курсу НБС на дату × коэффициент. Коэффициент задаётся вводом реального курса на сегодня: коэффициент = реальный курс / курс НБС сегодня (веб-настройки, MCP `set_real_rate`).
- Курсы НБС кешируются в `data/rates.json`. Если источник недоступен — берётся ближайший известный курс; курс можно задать вручную (MCP `set_rate`).
- Таргет и шаблоны фиксированных хранятся со своей валютой и пересчитываются по курсу 1-го числа месяца.

## 6. Способы ввода

1. **Диктовка в чат** — агент сразу записывает траты и отвечает таблицей записанного; при неясности (валюта, дата) сначала спрашивает. Дата по умолчанию — сегодня, валюта — валюта ввода.
2. **Скриншот** — агент считывает организацию, сумму, дату и время, показывает черновик (`dry_run`) с возможными дублями и записывает после подтверждения.
3. **Ручной ввод в вебе** — обязательные поля: сумма, название; предзаполнены: дата (выбранный день), валюта (валюта ввода); необязательные: категория, комментарий, тип (регулярная / нерегулярная + «сверх бюджета»).

Правила для всех способов:
- Тип по умолчанию — регулярная. Если пользователь назвал трату нерегулярной, но не сказал про «сверх бюджета», агент уточняет.
- Категория не указана → подбирается по правилам «название → категория», иначе «Без категории».
- Переводы между своими счетами и пополнения не записываются; возвраты — отрицательной суммой.
- Возможный дубль — трата с той же датой, суммой и валютой. Дубли не блокируют запись, а возвращаются как предупреждение.

## 7. Модель данных

Трата:
```jsonc
{
  "id": "e_7f3a9c",
  "date": "2026-10-04",
  "time": "13:42",            // опционально
  "name": "Maxi",             // обязательно
  "amount": 1250.0,           // обязательно, в исходной валюте; < 0 — возврат
  "currency": "RSD",
  "category": "groceries",    // опционально (null — «Без категории»)
  "kind": "regular",          // regular | irregular | fixed
  "over_budget": false,       // только для irregular
  "note": "",
  "source": "chat",           // chat | screenshot | manual | fixed
  "fixed_id": null            // id шаблона для kind=fixed
}
```

Категории (настраиваемые): продукты, рестораны, кофе, доставка еды, такси, транспорт, здоровье, одежда, дом, развлечения, подписки, связь, жильё, путешествия, подарки, прочее.

Файлы (`data/` в `.gitignore`, путь переопределяется `BUDGET_DATA_DIR`):
```
data/
  settings.json            базовая валюта, валюта ввода, категории, правила категорий
  targets.json             {"2026-10": {"amount": 3000, "currency": "EUR"}}
  fixed.json               шаблоны фиксированных трат
  rates.json               {"2026-10-02": {"EUR": 117.4948, "USD": 104.4027}} — RSD за единицу
  expenses/2026-10.json    {"fixed_applied": [...], "expenses": [...]}
```
Запись атомарная (временный файл + rename) под файловой блокировкой, чтобы веб и MCP не испортили данные при одновременной записи.

## 8. MCP-инструменты

| Инструмент | Что делает |
|---|---|
| `ensure_web_app` | проверить, что веб-приложение запущено, и запустить его, если нет; вернуть url |
| `get_settings` | базовая валюта, валюта ввода, категории, правила категорий, шаблоны фиксированных, таргет текущего месяца |
| `add_expenses(items, dry_run)` | пакетное добавление; `dry_run` — черновик без записи: суммы в базовой валюте, подобранные категории, возможные дубли; после записи ещё `budget_status` (на сегодня) и `page_url` (страница дня, при нескольких днях — дашборд) |
| `list_expenses(date_from, date_to, kind, category, query)` | выборка трат |
| `update_expense(id, …)` / `delete_expense(id)` | правка / удаление; тоже возвращают `budget_status` и `page_url` |
| `get_budget_status(date)` | остаток месяца, лимит на день и неделю |
| `get_summary(date_from, date_to, group_by)` | разбивка по категориям / названиям / дням / типам |
| `get_month_report(month)` | итог месяца (раздел 3) |
| `set_category_rule(pattern, category)` | запомнить «название → категория» |
| `set_rate(date, currency, rsd_per_unit)` | задать официальный курс вручную, если источник недоступен |
| `set_real_rate(currency, rsd_per_unit)` | реальный курс обмена на сегодня → коэффициент к курсу НБС |
| `set_target`, `add_fixed_expense`, `update_fixed_expense`, `delete_fixed_expense`, `update_settings` | настройки — только по явной просьбе пользователя (дублируют веб-настройки, нужны до появления веба) |

Правила поведения агента (раздел 6) лежат в инструкциях MCP-сервера, поэтому работают в любом клиенте Claude.
Сводка бюджета после записи возвращается прямо в ответе пишущих инструментов: агенту не нужно помнить об
отдельном вызове `get_budget_status`.

## 9. Веб-интерфейс (Flask + Jinja2 + Chart.js)

Серверный рендер и обычные формы; htmx не понадобился. Запуск: `uv run budget-web` → http://localhost:5050 (порт 5000 на macOS занят AirPlay).

1. **Дашборд** — таргет / потрачено / остаток; крупно «сегодня можно» и «на неделю осталось»; график темпа (накопленные траты против идеальной линии); последние 14 дней против лимита; категории за месяц; блоки фиксированных и нерегулярных.
2. **Календарь** — месяц, у каждого дня лимит и факт (зелёный/красный); клик — траты дня, добавление, правка, удаление.
3. **Операции** — таблица с фильтрами (период, категория, тип, название), поиск, массовая смена категории.
4. **Аналитика** — итог месяца, топ названий, категории по месяцам, сравнение с прошлым месяцем, траты по дням недели.
5. **Настройки** — базовая валюта, валюта ввода, таргет, фиксированные траты, категории, правила категорий.

## 10. Этапы

1. Ядро: модели, хранение, сервис, курсы, логика бюджета, тесты.
2. MCP-сервер, подключение к Claude, обкатка на реальных скриншотах и диктовке.
3. Веб: ручной ввод, календарь, операции, настройки, дашборд.
4. Аналитика.

Вне скоупа: бэкап, хранение скриншотов, способ оплаты (карта/наличные), банк.
